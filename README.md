# 代理规则配置库

## 项目速览

| 项目 | 说明 |
| --- | --- |
| 中文名称 | 代理规则配置库 |
| GitHub 仓库名 | `CLASH` |
| 名称状态 | 保持当前名称，本轮没有改名 |
| 主要用途 | 保存 Clash 系列客户端的订阅转换模板、分流规则、基础 YAML，以及 Quantumult X、Storm 等工具使用的辅助脚本 |
| 项目类型 | 配置与规则集合，不是代理客户端，也不提供代理服务 |
| 使用方式 | 选择需要的配置或规则，检查内容后导入自己已有的兼容客户端/订阅转换服务 |

> 这个仓库包含多个时期、不同用途的配置。文件名带日期或“修改”的内容可能是历史版本，不能默认全部同时使用。导入前必须检查规则来源、远程链接、代理组名称和客户端兼容性。

## 仓库里有什么

### 根目录的 `.ini`

根目录保存多份订阅转换模板，例如 `全.ini`、`CLASH 10.11.ini` 和若干按日期命名的历史配置。此类文件主要定义：

- 远程规则集地址；
- 国内外流量、AI、GitHub、媒体、游戏等分流组；
- 手动选择、自动测速、直连、拦截和漏网流量策略；
- 订阅转换时使用的规则与代理组组合。

这些文件之间存在重复和演进关系。使用前先选定一份主配置，不要把多份模板机械合并。

### `rules/`

按用途拆分的规则列表，包括 AI、Apple、GitHub、Telegram、TikTok、YouTube、微软、游戏、国内外媒体、直连、拦截和 IP 归属地等类别。这些列表可由根目录的转换模板通过 GitHub Raw 地址引用。

### `clash-rule-base-v22-domain-sniffer.yaml`

Clash/Mihomo 基础配置示例，重点配置域名嗅探、TUN DNS 劫持和 `fake-ip`，用于改善只能看到目标 IP、域名规则无法命中的情况。文件中的端口、DNS、TUN 和局域网访问设置必须按自己的设备调整。

### `QuantumultX/` 与 `storm/`

保存 Quantumult X、Storm 等客户端使用的脚本或规则片段。脚本会参与网络请求处理，只应在阅读代码、确认目标域名和行为后启用。

## 基本使用方法

1. 确认自己使用的客户端及其支持的配置格式。
2. 如果使用订阅转换服务，从根目录选择一份 `.ini` 作为模板，并核对其中引用的所有远程地址。
3. 如果只需要某一类分流，可单独引用 `rules/` 中对应的 `.list` 文件。
4. 如果需要解决域名嗅探问题，可把 `clash-rule-base-v22-domain-sniffer.yaml` 作为参考基础配置，再按客户端文档调整。
5. 导入后先检查配置语法、代理组是否存在、规则顺序是否合理，再用少量网站或应用验证命中结果。
6. 出现断网、DNS 异常或分流错误时，立即停用新配置并恢复之前的可用版本。

## 注意事项

- 仓库不包含 Clash、Mihomo、Quantumult X、Storm 等客户端，需要自行安装并遵守相应软件许可。
- 配置中的 Raw 链接可能指向本仓库或第三方仓库；第三方内容更新后行为也可能变化。
- 不要提交真实订阅地址、节点信息、认证参数、控制器密钥或私人域名。
- `allow-lan`、DNS 监听和外部控制器等选项会影响本机网络暴露面，使用前应理解其含义。
- 规则只能决定流量处理方式，不能保证隐私、匿名性、地区可用性或服务合规性。
- 修改前保留当前可用配置；历史模板是否仍适用，应以实际客户端校验结果为准。
